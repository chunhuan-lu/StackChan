## 发现（基于官方 v1.5.1 源码，并在 v1.6.0 上复查）

- 下载慢（约 20 KB/s）：StackChan 自己的 OTA 和应用商店下载路径从来不关闭 Wi-Fi 省电模式（上游小智在 OTA 前会切到 PERFORMANCE），
  而且 Wi-Fi 接收缓冲区和 TCP 窗口都很小（`sdkconfig.defaults`）。1.6 没有改动这部分。
- 说话卡顿吃字：可能是网络丢帧，也可能是解码任务被抢占。`opus_codec`（优先级 2）低于 LVGL 和 stackchan 任务（优先级 3）；
  `_stackchan_update_task` 会拿着 LVGL 锁睡 100 ms。设备主人反馈 OTA 到 1.6 后说话效果已经很好。
- 远程遥控卡顿：经过云端中转，加上 Wi-Fi 省电，再加上"一次取完队列、只执行最后一个目标"的动作处理方式。
  1.6 新增了局域网控制：手机 App 开一个 WebSocket 服务端，先通过云端通道告诉设备自己的地址，设备再直接连过去。
- 1.6 的其他变化：配网只能用 App（这块板子禁用并隐藏了热点、声波、BluFi 三种方式）；新增网络诊断；
  小智补丁改为丢弃社区版的激活码。
- 自编译固件无法和官方 App、官方云配对：公开仓库里的 `secret_logic` 只是一个弱符号占位实现。
- 唤醒词："Hi, Stack Chan"（`wn9_histackchan_tts3`，WakeNet9），只在 AI Agent 模式下生效。

## 首次测试后的改进；关闭服务器推送 OTA

维护者：按测试发现的问题改进；已审阅的提交可以推送；关掉 OTA 推送。

- 轻拍后误报"被拿起"：拍头会震动 IMU。现在头部被触摸期间、以及最后一次触摸事件后 1.5 秒内（`kTouchQuietMs`），
  暂停"被拿起"检测。
- 照度阈值：传感器在前面板玻璃后面，开台灯也只有 11–16 lux → `SC_IDLE_DARK_LUX` 从 5 改为 3，
  `SC_IDLE_BRIGHT_LUX` 从 20 改为 8（还要在关灯时确认）。
- 第一次照度读数为 0.0：`Hal::getAmbientLux()` 在初始化传感器的那次调用里直接返回"没有读数"，
  这样第一个值来自一次完整的 100 ms 测量。
- 时区：`SBT-11`（努美阿）没有夏令时，从 4 月第一个星期日起会快一小时。
  在「设置 → 系统 → 时区」里新增"Melbourne (AEST/AEDT)"（`AEST-10AEDT,M10.1.0,M4.1.0/3`），并把它设为 fork 的默认时区
  （`SC_DEFAULT_TIMEZONE`）。时区按 POSIX 字符串保存，所以在列表中间插入一项不会让已保存的选择错位。
  设备会继续使用 NVS 里的值（`SBT-11`），直到在设置里选择 Melbourne。
- 新增 `SC_DISABLE_REMOTE_OTA`（默认开启，在 fork 补丁里）：不再注册仅限用户调用的 MCP 工具 `self.upgrade_firmware`
  和 `self.assets.set_download_url`，服务器无法再推送固件或资源包（资源包会覆盖自定义唤醒词模型）。
  之前保存过的资源下载地址会记日志、删除并忽略。加上 `SC_DISABLE_AUTO_OTA`，只有在「设置 → 关于」里手动发起才会更新。
- 编译（全新 sdkconfig）：通过，fork 文件没有警告，`stack-chan.bin` 3.59 MB（剩余 27 %）。在固件二进制里确认：
  `self.upgrade_firmware` 和 `self.assets.set_download_url` 已经不存在；"Ignoring pushed assets URL" 和
  "automatic OTA disabled" 都在。
- 到 `cf6a49a` 为止的提交经审阅后已推送。本日志之前误记为 2026-10-21，现已合并到这里。
