## Idle behaviour, batch 1 (REQ-002, branch `feat/idle-behavior`)

- Branched from `feat/wake-word` (not `dev`) because it builds on the `SC_` Kconfig menu and the fork patch mechanism;
  will be rebased onto `dev` once REQ-001 is verified and merged.
- Maintainer decisions: whole batch 1, silent, awake 08:00–23:00, quiet (few head moves).
- Code review findings that shaped the design:
  - `BreathModifier` moves the features by deltas every 600 ms and ignores the avatar lock → face animations apply
    positions as relative offsets, otherwise the face would drift.
  - `BlinkModifier` restores saved eyelid weights → the avatar is locked while an animation or the sleep pose is active.
  - LED 0 is the conversation status LED, LEDs 0–5 / 6–11 are the left / right neon lights → the mood light writes
    LEDs 1–5 and 7–11 directly, at most 10 Hz, only when the colour changes.
  - `removeModifier()` destroys immediately under the display lock → the destructor restores the face, backlight and LEDs.
    On the battery power-save path (`SetEmotion("sleepy")` then removal) it keeps the sleepy face.
  - Head touch already reports Press / Release / SwipeForward / SwipeBackward; `HeadPetModifier` only handles swipes,
    so taps and long press are new and do not conflict.
  - The system clock is shifted by the timezone offset during xiaozhi's OTA check and corrected by SNTP later; the
    default timezone is `GMT0` → schedule only after SNTP sync, fork default timezone `CST-8`.
  - The LTR-553 ambient light sensor had no driver → minimal ALS driver (registers checked against the datasheet).
- Build: the first build failed because an incremental build does not pick up new Kconfig options (the director file
  compiled to nothing behind `#if CONFIG_SC_IDLE_DIRECTOR`, only `hal_rtc.cpp` failed). Fixed with `idf.py reconfigure`.
  Second error: fmt needs a constant format string. Final build passes; `stack-chan.bin` 3.59 MB (27 % free);
  no warnings from the new files; `IdleDirectorModifier` confirmed in the link map.
- **Not yet verified on the device.** First test should also record the logged lux values and gravity vector to tune
  thresholds and calibrate the IMU axes.
- Commits stay local until the maintainer has reviewed them.
