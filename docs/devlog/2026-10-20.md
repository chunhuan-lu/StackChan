## Findings (source review of official v1.5.1, rechecked on v1.6.0)

- Slow downloads (~20 KB/s): StackChan's own OTA / App Center paths never leave Wi-Fi modem sleep (upstream xiaozhi switches to
  PERFORMANCE before OTA), and Wi-Fi RX buffers / TCP window are small (`sdkconfig.defaults`). Unchanged in 1.6.
- Choppy TTS: likely frame loss (network) or decode starvation; `opus_codec` (prio 2) runs below LVGL and the stackchan task (prio 3);
  `_stackchan_update_task` sleeps 100 ms while holding the LVGL lock. Device owner reports speech is good on 1.6 after OTA.
- Laggy remote control: cloud relay + modem sleep + "drain the queue and retarget" motion handling. 1.6 adds LAN control
  (phone app hosts a WebSocket server, the device connects to it after an endpoint announcement over the cloud channel).
- 1.6 also: App-only Wi-Fi provisioning (hotspot / acoustic / BluFi disabled and hidden for this board), network diagnostics,
  and the xiaozhi patch now discards community activation codes.
- Self-built firmware cannot pair with the official App or cloud: `secret_logic` is a weak stub in the public repo.
- Wake word: "Hi, Stack Chan" (`wn9_histackchan_tts3`, WakeNet9), active only in AI Agent mode.

## Idle behaviour, batch 1 (REQ-002, branch `feat/idle-behavior`)

- Branched from `feat/wake-word` (not `dev`) because it builds on the `SC_` Kconfig menu and the fork patch mechanism;
  will be rebased onto `dev` once REQ-001 is verified and merged.
- Maintainer decisions: whole batch 1, silent, awake 08:00–23:00, quiet (few head moves).
- Code review findings that shaped the design:
  - `BreathModifier` moves the features by deltas every 600 ms and ignores the avatar lock → face animations apply
    positions as relative offsets, otherwise the face would drift.
  - `BlinkModifier` restores saved eyelid weights → the avatar is locked while an animation or the sleep pose is active.
  - LED 0 is the conversation status LED, LEDs 0–5 / 6–11 are the left / right neon lights → the mood light writes
    LEDs 1–5 and 7–11 directly, at most 10 Hz, only when the colour changes.
  - `removeModifier()` destroys immediately under the display lock → the destructor restores the face, backlight and LEDs.
    On the battery power-save path (`SetEmotion("sleepy")` then removal) it keeps the sleepy face.
  - Head touch already reports Press / Release / SwipeForward / SwipeBackward; `HeadPetModifier` only handles swipes,
    so taps and long press are new and do not conflict.
  - The system clock is shifted by the timezone offset during xiaozhi's OTA check and corrected by SNTP later; the
    default timezone is `GMT0` → schedule only after SNTP sync, fork default timezone `CST-8`.
  - The LTR-553 ambient light sensor had no driver → minimal ALS driver (registers checked against the datasheet).
- Build: the first build failed because an incremental build does not pick up new Kconfig options (the director file
  compiled to nothing behind `#if CONFIG_SC_IDLE_DIRECTOR`, only `hal_rtc.cpp` failed). Fixed with `idf.py reconfigure`.
  Second error: fmt needs a constant format string. Final build passes; `stack-chan.bin` 3.59 MB (27 % free);
  no warnings from the new files; `IdleDirectorModifier` confirmed in the link map.
- **Not yet verified on the device.** First test should also record the logged lux values and gravity vector to tune
  thresholds and calibrate the IMU axes.
- Commits stay local until the maintainer has reviewed them.

## Fixes after the first test; server-pushed OTA disabled

Maintainer: improve what the test found, push the reviewed commits, switch off OTA push.

- False pick-up after taps: touching the head jolts the IMU. Pick-up detection now pauses while the head is touched and
  for 1.5 s after the last touch event (`kTouchQuietMs`).
- Lux thresholds: the sensor sits behind the front glass and a desk lamp gave only 11–16 lux → `SC_IDLE_DARK_LUX` 5 → 3,
  `SC_IDLE_BRIGHT_LUX` 20 → 8 (to be confirmed with the light switched off).
- First lux reading 0.0: `Hal::getAmbientLux()` now returns "no value" on the call that initialises the sensor, so the
  first value comes from a completed 100 ms measurement.
- Timezone: `SBT-11` (Noumea) has no daylight saving and would be one hour ahead from the first Sunday in April.
  Added "Melbourne (AEST/AEDT)" (`AEST-10AEDT,M10.1.0,M4.1.0/3`) to Settings > System > Timezone and made it the fork
  default (`SC_DEFAULT_TIMEZONE`). The setting is stored as the POSIX string, so inserting an entry does not shift saved
  choices. The device keeps its NVS value (`SBT-11`) until Melbourne is chosen in the settings.
- New `SC_DISABLE_REMOTE_OTA` (default y, fork patch): the user-only MCP tools `self.upgrade_firmware` and
  `self.assets.set_download_url` are not registered, so the server can no longer push a firmware image or an assets
  package (an assets package would replace the custom wake word model). An assets download URL saved earlier is logged,
  erased and ignored. Together with `SC_DISABLE_AUTO_OTA`, updates only happen when started by hand from
  Settings > About.
- Build (fresh sdkconfig): passes, no warnings from fork files, `stack-chan.bin` 3.59 MB (27 % free). Checked in the
  binary: `self.upgrade_firmware` and `self.assets.set_download_url` are gone; "Ignoring pushed assets URL" and
  "automatic OTA disabled" are present.
- Commits up to `cf6a49a` pushed after review. This devlog was first filed as 2026-10-21 by mistake and is merged here.
- **Not yet flashed.**
