## 真机：做完网络测试后重启进入 App 配置页（官方 bug，B-018）

固件：`feat/idle-behavior` 的 `5ef1a3c`（待机调优、墨尔本时区、`SC_DISABLE_REMOTE_OTA`）。

- 「设置 → 系统」：时区改成"Melbourne (AEST/AEDT)"，重启后仍然保留
  （`load timezone from nvs: AEST-10AEDT,M10.1.0,M4.1.0/3`）。✔
- 「设置 → 网络测试」：Wi-Fi 启动并连上，小智 `available`，M5Stack `reachable`。
- 大约 7 分钟后进入 AI Agent：日志先是 `WifiManager: Already initialized`、`Station already active`，60 秒后出现
  `WiFi connection timeout, entering config mode` → `WiFi setup required; opening StackChan App setup` → 软件复位
  （`RTC_SW_CPU_RST`，不是 panic；当时内部 SRAM 还剩约 74 KB）。
- 重启后启动页日志是 `resume App setup after network/binding failure`，显示了 APP SETUP 页面并打开蓝牙配网，
  看起来像是设备被解绑了。
- 原因（看源码得出）：网络测试直接通过 `WifiManager` 打开 Wi-Fi，退出后也不断开。`WifiBoard::TryWifiConnect()`
  启动 60 秒计时器，等待一个早已发生过的 `Connected` 事件；而开发板代码把"进入配网模式"处理成 `requestAppSetup()`
  （写一次性的 NVS 标记，然后重启）。这些文件 fork 都没有改过，所以官方 1.6.0 也会这样。
- 没有丢失任何数据：小智绑定在服务器上，`app_config/is_configed` 没有被改动，Wi-Fi 密码也都在。
  维护者按了 RST 之后，回到正常桌面，AI Agent 又能正常使用了。✔
- 记录为 B-018；按维护者的决定暂不改代码。临时办法：做完网络测试先重启。

## 用了一晚后的反馈；REQ-004（分支 `fix/standby-power`）

维护者反馈：睡觉时屏幕太暗；插 USB 时不要待机；长时间待机后重启了一次，看起来像 Wi-Fi 导致的崩溃。

调查（5 项并行的源码和原理图调研，其中 4 项另有一轮反驳式复核）：
- 重启是 AI Agent 的 Home 按钮触发的（上滑再点 Home，维护者确认）。离开 AI Agent 一定会重启；Wi-Fi/TLS 报错来自
  `esp_restart()` 关闭 Wi-Fi。没有崩溃。顺带发现：点一下睡着的暗脸会开始一次对话（待机行为不响应屏幕触摸），
  从底边上滑也可能触发开始/结束对话。
- 睡眠亮度 5 已经是最暗的可见档（AXP2101 DLDO1，9 档、每档 100 mV；1–12 都是 2.5 V）。
- 插着 USB 时，官方省电计时器本来就是关闭的，除非 PMIC 报告电池在放电。舵机永远经机身升压电路直接用电池（看原理图），
  所以"完全不靠电池"做不到；机身的 INA226（0x41）能测到真实的电池电流。固件里的"外部供电"标志从来没读过 VBUS。
- Claude Code 状态机器人：经原生 USB-Serial/JTAG 的 USB 通道可行（约 1 KB 内部内存）；MQTT 中转可行
  （约 5–8 KB 内部内存，任务栈只能放内部内存）。HiveMQ 的免费版将在 2026-12-31 停止服务。

决定：插 USB 时保留夜间作息；开灯时睡眠亮度 45；Home 不需要长按确认。Claude Code 方案的回答记录在
[REQ-003](../requirements/REQ-003-claude-code-status.zh-CN.md)（会话多在 WSL、Python 后台程序、NAS 有静态 IP、
工作时间静音、气泡显示项目名加事件）。

实现（见 [REQ-004](../requirements/REQ-004-standby-power-touch.zh-CN.md)）：睡眠亮度分暗/亮两档并渐变、睡着时点屏幕叫醒、
过滤滑动、Home 滑动过程中忽略点击并在重启前显示"Going home..."、检查 FT6336 采样、记录复位原因、崩溃转储写入 flash、
按 VBUS 防抖判断外部供电并记录供电日志（含 INA226 电池电流）、插 USB 时不进省电、状态栏显示闪电、退出省电时重启待机行为。

对改动做了代码审查（4 个方向，每条发现都经过复核），确认 6 个真实问题，全部修复：
- 在「设置」里点 Home 但不需要重启时，"Going home..." 遮罩会一直盖在桌面上（现在由指示器持有并在销毁时删除、
  不响应点击，并且只在真的要重启时显示）；
- `Backlight::SetBrightness` 在有待执行的渐变时会忽略第二次调用，导致房间黑时省电模式的调暗被吞掉
  （在小智 fork 补丁里修复：有待执行的渐变时也改目标值）；
- 在只有 4 KB 栈的 stackchan 任务里调用 `lv_refr_now()`（现在由 LVGL 任务绘制遮罩，300 毫秒后再返回主页）；
- Home 按钮快要收起时点的那一下会被丢掉；省电调暗和唤醒之间有竞争；异常的触摸采样被当成手指抬起
  （现在直接丢弃，连续 5 次才当作抬起）；
- 平时亮度为 0 时，睡眠亮度反而会把屏幕点亮。

编译（全新 sdkconfig，ESP-IDF 5.5.4）：通过，改动的文件没有警告，`stack-chan.bin` 3.60 MB（剩余 27%）。
崩溃转储预留了 1.8 KB 内部内存栈（已关闭崩溃转储的日志字符串）。**尚未刷机。**
