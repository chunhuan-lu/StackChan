- 阅读代码时的发现，以及它们对设计的影响：
  - `BreathModifier` 每 600 ms 按增量移动五官，而且不检查 avatar 锁 → 表情动画的位置改用相对偏移，否则脸会慢慢漂移。
  - `BlinkModifier` 会恢复它之前保存的眼皮位置 → 播放动画或处于睡姿时，锁住 avatar。
  - LED 0 是对话状态指示灯，LED 0–5 和 6–11 分别是左、右灯条 → 心情灯直接写 LED 1–5 和 7–11，每秒最多 10 次，只在颜色变化时写入。
  - `removeModifier()` 会在持有显示锁的情况下立即销毁对象 → 由析构函数恢复表情、背光和灯光。
    在电池省电路径上（先 `SetEmotion("sleepy")` 再移除调度器），保留困倦的表情。
  - 头顶触摸本来就会上报 Press / Release / SwipeForward / SwipeBackward 四种事件；`HeadPetModifier` 只处理"撸"，
    所以新增的轻拍和长按不会和它冲突。
  - 小智的 OTA 检查会把系统时钟按时区偏移拨动，之后再由 SNTP 校正回来；默认时区是 `GMT0`
    → 作息只在 SNTP 同步后才生效，fork 的默认时区改为 `CST-8`。
  - LTR-553 环境光传感器原本没有驱动 → 写了一个只读环境光的最小驱动（寄存器已对照数据手册核对）。

  第二个错误：fmt 要求格式字符串必须是常量。最终编译通过；`stack-chan.bin` 3.59 MB（剩余 27%）；
  新文件没有产生警告；已在链接 map 中确认 `IdleDirectorModifier` 被链接进固件。

## 第一次真机测试（feat/idle-behavior，包含 REQ-001），当地时间 2026-10-20 23:07–23:13

用 `idf.py -p COM12 flash` 刷机，所有区域都校验通过。因为设备是按住 RST 手动进入的下载模式，刷完后仍停在 ROM 引导程序里（串口没有输出），
短按一下 RST 后固件才启动。串口日志用工作区里的 `tools/serial_log.py` 录制。没有崩溃、panic 或看门狗复位。

REQ-001（唤醒词）：
- 从 NVS 读到 Wi-Fi 并自动重连，不需要重新配网。✔
- OTA 检查显示 "Current is the latest version"，MQTT 连接成功，"Activation done"：自编译固件可以沿用现有的小智绑定，不会跳到 App 绑定页面。✔
- 6080 KB 的资源分区挂载成功，校验通过；加载了 `mn7_cn`，命令词 `qi lai gan huo`、文字 `起来干活`，阈值 0.2。✔
- 日志里有两次用"起来干活"唤醒（置信度 0.319 和 0.343）；对话、工具调用（查天气）、音色都正常；维护者反馈"还不错"。
  10 次命中率、说 "Hi Stack Chan" 不应唤醒的反向测试、误唤醒测试：都还没做。
- 关闭自动 OTA 的代码路径还没被触发（目前没有更新的官方版本）。

REQ-002（待机行为）：
- 每次对话结束后调度器都会启动，被唤醒时停止；睡着时说唤醒词也能正常唤醒，背光也恢复了（5 → 75）。✔
- SNTP 同步后的当地时间是 23 点（设备时区从 NVS 读取：`SBT-11`，维护者在墨尔本）→ 每次对话结束 60 秒后打瞌睡入睡，
  符合 23:00–08:00 睡觉的设定。✔
- 轻拍 3 下 → 生气（出现两次）。✔ 拿起、放下都检测到了（能量值 3.53、6.42、2.90）。✔
  有一次"被拿起"出现在连续轻拍后 200 毫秒，可能是拍头时把 IMU 震动了（误报）。
- 约 6 分钟里挑选的行为：什么都不做 ×3，转头张望 ×1（符合安静的预期）；没有发出任何声音。✔
- 夜里开着台灯时的环境光是 11–16 lux；传感器初始化后的第一次读数是 0.0（当时还没有完成一次测量）。
  `SC_IDLE_BRIGHT_LUX` 设为 20 的话，开着台灯也不会被判定为"开灯"。
- IMU 标定数据：重力主要在 +Y 轴上，头部俯仰是绕 X 轴转动；俯仰角 ≈ atan2(gz, gy)：接近睡姿时 7.8–8.6°，转头张望后 24.7°
  → 头部保持水平可以用"身体倾斜 = 测得的俯仰角 − 舵机俯仰角"来计算。
- 还没测：天黑睡觉/开灯醒来、轻拍 6 下、长按、撸毛余韵、倾斜、早上起床。
